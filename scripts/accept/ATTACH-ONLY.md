# 不能进隔离批跑的验收脚本（附原因）

## 一、attach-only（自己不启动应用）

这三条用 `chromium.launch({ executablePath: ".../chrome.exe" })` 起一个浏览器，
再连到**已经在运行的实例**的调试端口。所以它们：

- 读写的必然是**真实 userData**（不是隔离目录）；
- 在串行批跑里会连到**上一条脚本残留的实例**，结果随顺序变；
- 要收进批跑，得先把它们改写成"自己启动应用 + 隔离数据目录"——
  这不是加一行环境变量能解决的。

| 脚本 | 缺什么 |
|---|---|
| `accept-final.mjs` | 应用生命周期 + 数据目录隔离 |
| `accept-image.mjs` | 同上 |
| `accept-p2.mjs` | 同上 |

## 二、已补隔离、但仍失败

`accept-p3.mjs` 本来**自己启动应用**，只是漏了数据目录隔离 —— 已补：
`DSH_CANVAS_DATA_DIR` + 统一的调试端口（原来 `env` 里写一个、CLI 里写另一个 `9222`、
`connectOverCDP` 又写死 `9222`，三处不一致）。

补完**连得上 CDP 了**（过了原来的失败点），但**又卡在后面的 `locator.fill` 超时** ——
说明它**还有未识别的状态依赖**（或选择器过期）。**未查明，不放进批跑。**

## 三、判据（写给下次）

加一条验收进批跑之前，先查三件事：

1. **它自己启动应用吗？**（不是的话 → attach-only，不能隔离）
2. **它设了 `DSH_CANVAS_DATA_DIR` 吗？**（没设 → 会污染真实目录与后续条目）
3. **它真的不调模型吗？**（读脚本里有没有 `gen-run` / `chat-send` / `wb-send`）
