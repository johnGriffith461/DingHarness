# 诚实边界

这一页只做一件事：把**没有做到 / 没有验证 / 不能保证**的事列清楚。
官方口径的完整清单在 `SAFETY.md` 与 `BENCHMARKS.md`，这里是给第一次来的人看的摘要。

## 数字

- `ding eval` 的 63 条是**过程回归**（脚本化 provider），它证明"编排、工具、闸门、
  恢复能走通"，**不证明模型智能**。
- `ding bench` 的 7 条是**任务级基准**（判文件与命令），同样不花 API 钱、
  模型回复是脚本化的。
- **SWE-bench 没有成绩。** 适配层能生成官方格式的预测，但判分要官方 harness；
  没有跑过就不写数字。

## 平台

- 桌面只有 **Windows x64** 打包并启动验过；macOS/Linux 的桌面**没在真机上跑过**。
- **源码级门在 Linux 上验过**（2026-10-18，WSL Ubuntu / Node 22）：`typecheck`、`lint` 绿，
  全量单测 **309 文件 / 3497 条通过**（6 条 Windows 专属断言跳过）；CI 已加
  `ubuntu-latest` 一格固化它。**macOS 没跑过**，所以没有 macOS 那一格。
- CLI 的 npm 路线只在 Windows 上执行过（**2026-10-18 干净安装复验**：空缓存空前缀装
  `ding-harness@0.5.1`，版本对、`eval` 63/63）；macOS/Linux 的 npm 安装**没跑过**。
  单二进制在 WSL Ubuntu 上跑过 `eval`。
- `run_command` 的资源上限（作业对象）**只有 Windows**；macOS/Linux 没有
  （但中止信号在 Linux 上改成杀**进程组**，实测从"40 秒才返回"变成约 0.3 秒）。

## 安全

- **没有真正的沙箱**：命令以你的身份运行，闸门是唯一拦住破坏性操作的东西。
- 插件跑在独立 Worker（G18）：崩溃/死循环隔离；`fs:read` / `fs:write` / `exec` 由 Node 权限模型强制
  （只能碰插件目录、写要批准、起子进程要批准）。**`net` 仍拦不住**（Node 没有网络权限那一格）。
  宿主不支持权限模型时只隔离崩溃，界面会标 `worker`。
- 同步：内容层 E2EE，但**控制事件（审批/接管）明文**（ADR-0014 的取舍）。
- CLI 的密钥是**明文文件**（没有系统钥匙串入口）；桌面走系统加密存储。
- 自动更新未做（需要代码签名与更新 feed）。

## 完整性

- 移动端没有（V7 候选）。
- RAG 知识库是**本地 FTS5 + LIKE**（零模型调用），不是向量语义检索；桌面面板与 CLI 用同一个库文件。
- 遥测默认关闭；OTLP 不配环境变量就一个请求都不发。
- 崩溃**只落本机**（`<数据目录>/crashes.jsonl`，最近 50 条、写盘前脱敏）；
  没有崩溃上报服务 —— "可选上报"在这里就是"导出诊断包给你自己交给谁"。
