## 背景

闸门此前只回答"要不要拦"（工具轴），不回答**"拦下了归谁处置"**：
待决项是一个**无主**的 pending 留痕 —— 谁点都算。单机单用户时这是对的，
V5 的 C2/C3 一旦引入成员，它就是权限缺口："谁能处置这条"必须是一个能被查询、
能被流转、能被审计的属性。

同时要保住一条既有的硬结论：**待决状态不另立一种事件类型**（gates.ts 文件头那段
"刻意的 不做"）—— 重启后可恢复、决策可审计、旧日志可读三件事，现有记录形状已经满足。
本 ADR 继续沿用它：新属性加在**载荷与决策记录**上，不新增事件类型。

## 决定

### 1. "待谁批"写在**拦下那一刻**

闸门拦下调用时，pending 载荷里带上 `approvers: [<会话 owner 的 id>]`
（执行上下文里的 `ctx.owner`，缺省 `"local"`）。**读的时候不现编**
（`approversOf` 只做三件事：取载荷里的 → 老载荷落默认 → 坏形状落默认）。

为什么钉在那一刻：**"谁能批"是拦下时就该定的事实**，与"后来谁在线"无关。
把归属做成读时推导，就会随"成员表的当前状态"漂移 —— 而审计要回答的是
"当时这条归谁"，不是"现在归谁"。

### 2. 三态与一次性允许（对齐 DeepSeek-Bot）

- 状态机：`待决 → 已批准 | 已拒绝`（`cancelled` 那一支在 V5-1 没有载体 ——
  abort/离开会话的批量取消属 V5-3 的接管语义，记在 follow-ups）。
- **`allowed-once` 的语义**：批一次只对**那一次调用**生效，不是"以后这个工具都放行"。
  这一点本地实现天然成立（决策按 `toolCallId` 落到那一条留痕上），本 ADR 把它写成明文口径 ——
  将来做"记住这个选择"必须是另一件事（另一个入口、另一条记录），不许偷偷改这条。

### 3. 幂等 answer + stale 报错

处置前核对（`canDecide`）：**已经处置过 → `stale`**，回一句明确的话
（"这条待确认已经处置过了（重复点不会执行第二次）"），而不是又执行一遍。
判据从日志来（`decidedByOf`：日志里有一条同 `toolCallId` 的决策记录）——
只有**确凿**才算 stale。

⚠️ **核对不上就按老路径放行**（宿主接线处的口径）：`pending` 不在日志里可能只是
"这段日志被截过 / 不是同一个会话"，那种情况拦下来会挡住本来能用的路。
stale 的拒绝只用在"日志明确知道这条，且它已经处置过"。

### 4. 授权他人批（`authorizeApprover`）

现任审批人可以把裁决权**加**给别人（owner 授权 B 批，V5 §7 E2E-4 的那件事）。
规矩三条：

- 只有**现任审批人**能授权（不能自己挤进一张不属于自己的单子）；
- 目标是空 id → 输入问题（`invalid-target`）；
- 重复授权是**幂等**的（`added:false`，不算错）。

⚠️ 本轮**只做加法**：撤回授权（把某人移出集合）与"转交"（换而不是加）
都还没有客户 —— 它们牵涉"授权链"（B 能不能再转给别人），那需要先有
V5-3 的成员管理界面定下产品语义。记在 follow-ups 里，别顺手发明。

### 5. 谁批的记下来（`decidedBy`）

决策记录带 `decidedBy`（成员 id）与当时的 `approvers`。
老记录没有这两格 → **读回来按 `legacy` 兜底，不编"是 owner 批的"**
（与 C5 的 actor 同一条纪律：不知道就别编）。

## 明确不做的

- **不新增事件类型**（沿 gates.ts 的既有结论，理由在它的文件头）。
- **不建独立 approvals 表**：现在没有按审批维度的查询客户（"统计人类响应时长"那类）；
  等它出现时按 ADR-005 的链加一步迁移，而不是现在先建一张没人读的表。
- **不做批量取消**（`cancelled`）：它的载体是"接管/离开"（V5-3）。
- **不做"永久记住这个工具"**：与一次性允许是两件事（见决定 2）。

## 后果

- 待决项从"无主的 pending"变成**带归属、可流转、可审计**的对象；
  裁决权的判定与流转都是**纯函数**，矩阵式的测试在 `gates.test.ts`
  （含 3.7b 的验收：A 发起 → 授权 B → B 批准 → 事件留痕，记录进记录出）。
- 老路径零变化：本机单用户下 `approvers = [local]`、处置人 `local`，判定恒过；
  老日志（pending 载荷里没有 approvers）按默认审批人读。
- **已知边界（如实记）**：本机单用户阶段**没有第二种身份**，"没有裁决权"这条判定
  没有真实的拒绝场景 —— 它的正确性目前由纯函数测试保证；直到 V5-2 的成员 token
  接上，它才第一次真的会拦人。
