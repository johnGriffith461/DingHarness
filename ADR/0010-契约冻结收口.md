## 冻结什么、不冻结什么（一句话）

**冻结语义，不冻结表示。** V5 的三条新增不变量里的第一条就是它：
"语义契约与表示契约分离 —— V5-1 只冻结事件/权限/fork 语义，存储表示随引擎选型演进。"

| 契约 | 冻结的**语义**（改了要 ADR） | **不冻结**的表示（随选型演进） |
|---|---|---|
| C1 会话归属 | 每段会话有一个 owner；新建时定、之后不改；跨 owner 写拒/读不返回内容 | `sessions.owner` 这一列本身（换库/换表由迁移链管，ADR-005） |
| C2 成员-角色-权限 | 角色集合与**两轴矩阵**（角色是上限、档位是旋钮、deny≠ask） | 成员目录的持久化形态（现在在内存里）；`member_roles.scope` 未定 |
| C3 待决审批裁决权 | 待决带审批人集合；`stale` 与 `not-approver` 两种拒绝；一次性允许；授权只能由现任审批人加人 | 审批列表怎么算（现在是"整段日志现算"；将来说独立表也是表示） |
| C4 记忆归属域 | `private`/`team` 两级；注入按域过滤；旧数据按 private 读 | 记忆的存储文件（`memory.json` 的信封，jsonStore 管） |
| C5 事件 actor | 每条记录自描述"谁写的"；四种 kind；老记录读回 `legacy`；**不进投影指纹** | payload 里怎么放（现在是一个 `actor` 对象；列 `actor_id/actor_kind` 是索引表示） |
| C6 画布 | 八种事件名与折叠语义；归属在画布上；`revision = 最后 seq`；存量桥接等价 | 画布**存储与渲染引擎**（仍是 CanvasDocument 快照；event-sourced 写入是 V6） |

三条新增不变量各自的落点（"说得出在哪执行"）：

1. **语义与表示分离** —— 本 ADR 的这张表 + 迁移链（ADR-005：表示演进只加步骤，不动语义）；
2. **权限两轴统一表达** —— ADR-007 的矩阵（一个纯函数 `decideForMember`，工具轴与人轴同层）；
3. **身份向后兼容** —— actor 读回 `legacy`（ADR-006）、owner 默认 `local`（ADR-005 的 v4）、
   审批人默认 owner（ADR-008）、记忆默认 private（C4 的 normalize）、画布 owner 默认 `local`（ADR-009）。

## 变更程序（这就是 3.10b 的契约 diff 门）

冻结面可计算、可对账：`engine/core/contracts.frozen.json` + `src/contractFreeze.test.ts`。

改契约的正确做法（判词里也写着）：

1. **先写 ADR**（新的一份，或明确修订既有那份的哪一节），说明为什么改、谁受影响；
2. **再更新清单**（`contracts.frozen.json` 的对应项指向那份 ADR）；
3. 跑测试 —— 门的四条判据（清单↔代码两向对账、每项 ADR 真实存在、关键行为面当面复算）
   全绿才算改完。

⚠️ 门不判断改动好坏，它只保证**没有一次契约变更是无名的**。
（本轮已做变异实证：删一项 + 指向不存在的 ADR → 两条判据当场红。）

## 明确不做的

- **不冻结项目的对外 API 形态**（`EnginePorts`/`Engine` 的完整形状）—— 那是 V5-4
  （API 冻结清单 + compat 矩阵）的活；本轮只冻六项契约的语义面。
- **不把冻结面写成"永不可变"**：它可以变，只是**必须留名**（见变更程序）。
- **不承诺未验收的 U8**（见上）。

## 后果

- 后面的人（含 Qoder、含 V5-4 的第三方）拿到的是一张**可对账**的契约表：
  哪一项、为什么这么定、改动要留什么名。
- 门的维护成本是"改契约时多两步"；它换来的是"没有任何一次契约变更是无名的"。
- 已知边界（如实记）：清单覆盖的是**能计算**的那些面（枚举、矩阵、迁移版本、
  记录键集、default 值）；"语义的为什么"在 ADR 里，机器管不到——那部分靠评审。
